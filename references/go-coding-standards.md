 # Go 编码规范

 > **核心原则**: 代码风格严格统一，禁止在业务逻辑中使用 panic，错误处理必须独立分支。

 ## 代码风格 (🔴 强制)

 - **格式化**: 所有代码必须用 `gofmt` 格式化
 - **import**: 使用 `goimports` 自动管理导入包，分组顺序：**标准库** → **第三方包** → **内部包**，每组间空行分隔
 - **import 路径**: 必须使用完整路径，禁止相对路径（如 `"../net"`）
 - **行宽**: 建议不超过 120 列（import 语句、struct tag、生成代码除外）
 - **文件长度**: 不超过 800 行；单测文件不超过 1600 行
 - **函数长度**: 不超过 80 行；单测函数不超过 160 行
 - **嵌套深度**: 不超过 4 层
 - **魔法数字**: 出现超过 2 次必须定义为常量

 ## 错误处理 (🔴 强制)

 - `error` 作为返回值时必须处理，或显式赋值给 `_`。`defer xx.Close()` 除外
 - `error` 必须是最后一个返回值
 - 错误流必须独立分支，禁止 `if err == nil { ... } else { ... }` 模式
 - `error` 判断独立处理，不与其他条件组合（如 `if err != nil || y == nil`）
 - `errors.New("...")` 用于不需格式化的错误；`fmt.Errorf("module xxx: %w", err)` 用于包装错误
 - 错误描述末尾不需要标点
 - **类型断言**: 必须使用 `t, ok := i.(string)` 双返回值形式
 - **panic**: 业务逻辑禁止使用 panic；main 包只在不可运行时使用；可导出接口不能有 panic
 - **recover**: 只在 defer 中使用；每个自行启动的 goroutine 必须在入口处捕获 panic
 - **defer**: 紧跟资源获取后，禁止在循环中直接使用 defer（可用匿名函数包裹）

 ## 命名规范 (🔴 强制)

 - **文件命名**: 小写字母 + 下划线，如 `user_service.go`
 - **包命名**: 小写单词，与目录一致。**禁止**使用 `util`、`common`、`misc`、`global` 等无意义包名
 - **结构体**: 驼峰命名，名词短语，避免 `Data`、`Info` 等宽泛名称
 - **接口**: 驼峰命名，单方法接口以 `er` 后缀（如 `Reader`）
 - **变量**: 驼峰命名，局部变量倾向短命名（如 `c` 比 `lineCount` 好）
 - **常量**: 驼峰命名，枚举常量先创建类型：`type Scheme string`
 - **函数**: 驼峰命名，首字母根据访问控制大写/小写
 - **方法接收器**: 类名首字母小写（如 `s` for `*Service`），禁用 `this`、`self`、`me`
 - **特有名词**: 全大写/全小写规则（如 `APIClient`、`urlArray`、`UserID`），私有且为首单词时全小写

 ## 注释规范 (🔴 强制)

 - 每个导出的名字（包/结构体/函数/常量/变量/类型）必须有文档注释，格式：`// Name 描述`
 - 结构体内的导出成员如有歧义，必须在成员前或行尾加注释
 - 注释掉的代码在提交前必须删除（除非有明确保留理由和后续计划）

 ## 控制结构 (🔴 强制)

 - `if` 变量在左、常量在右（如 `if err != nil`，不写 `if nil != err`）
 - `if` bool 变量直接判断：`if allowLogin`、`if !allowLogin`
 - `range` 丢弃无需项用 `_`：`for key := range m`、`for _, value := range array`
 - `switch` 必须有 `default`
 - `goto` 禁止在业务代码中使用
 - `return` 尽早返回，错误发生后立即 return

 ## 函数设计 (🔴 强制)

 - 传入参数和返回参数均不超过 **5 个**
 - 函数参数超过 20 行时，接收器命名不用单字符
 - **传值与传指针选择**:
   - 值传递: 小/固定大小类型，不需修改原始数据，并发安全场景
   - 指针传递: 需修改原始数据，大型结构体，表示可选/nil 状态
 - map、slice、chan、interface 不要传递指针
 - **函数参数不超过 5 个**；**嵌套不超过 4 层**

 ## 单元测试 (🔴 强制)

 - 文件名: `example_test.go`
 - 函数名: `TestXxx` 或 `TestBar_Foo`
 - 每个重要的可导出函数必须编写测试用例，与正式代码一起提交

 ## 依赖管理 (🔴 强制)

 - Go 1.11+ 必须使用 `go modules`
 - `go.sum` 必须提交，不要添加到 `.gitignore`
 - 不建议提交 `vendor` 目录

 ---
 **执行检查点**: 检查 go 代码是否符合 gofmt 格式、import 分组规范、错误处理独立分支、panic/recover 合规、命名规范、控制结构及函数设计约束。
